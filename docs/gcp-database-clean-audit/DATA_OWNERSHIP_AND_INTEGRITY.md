## Authority and sensitive-state rules

- Global lesson/default vs class config override: one approved owner for each field; do not let API/trigger/JSON mirror independently redefine rubric or publication.
- Attempts/runs/Judge claims preserve paid outcome and exact immutable input evidence. Progress is a derived read model, attendance human fact, awards issued evidence; never merge/recompute those meanings.
- SOP contributions record requested target document (NULL may mean create); produced document derives through version. Binding tuple guard selected, not forced rewrite of intake history.
- JSON vectors are stored model-space evidence, generated pgvector column is a derived projection. Keep model/task/hash/dimensions/readiness metadata; do not relabel existing values. Owner-private contexts not shared corpus.
- SQL remains authority; BQ/Firestore are derived consumers with explicit idempotency, delete/revoke and retry/freshness contracts. Audit events do not substitute outbox delivery or private coaching notes.
- Membership/history state is not a permission shortcut. Current actor/class/course/client/domain/recipient matrix tested with real roles before internal refactor. Parent FK existence alone cannot prove authorized access.
- No default retention numbers introduced except existing 7-day nonce cleanup. PII/score/content/archive obligations require owner policy; keep old UUIDs, citation/certificate IDs and immutable source SQL/MVP history.
- Product owner decides meaning/scope, DB reviewer constraints/locks, operator recovery/backups, security owner IAM/retention. These are responsibilities, not new product personas or schema abstractions.
