## 1. Product Positioning

### What Promptify IS:
**Promptify is a Professional AI Playground with an Embedded Learning Layer.**  
It is an interactive workplace workbench where business professionals practice prompt engineering directly on authentic workplace tasks using live enterprise LLMs, receiving immediate automated rubric feedback to iterate and master AI deliverables.

### What Promptify IS NOT:
- **NOT a traditional LMS:** No video lectures, no lengthy theory walls, no passive multiple-choice quizzes with an isolated textarea tacked onto the bottom.
- **NOT a generic AI chat wrapper:** It does not drop the user into an empty, unguided chat window without guardrails, input datasets, evaluation criteria, or version tracking.
- **NOT an academic prompt engineering course:** No esoteric technical jargon, Python scripts, API tokens configuration demands, or abstract math concepts.

### The Core Product Principle:
> **"Output là đích, kỹ thuật prompt là phương tiện."**  
> *(Output is the destination; prompting techniques are merely the vehicle.)*  
> Business learners are not evaluated on how clever, verbose, or buzzword-laden their prompt is. They are evaluated strictly on whether the resulting AI deliverable is **accurate, grounded, policy-compliant, properly formatted, and immediately usable in business operations**.

## 2. Target User Profile

### Primary Demographic:
**Business & Non-Technical Professionals** (Mid-to-Senior Level, Corporate & SME):
- **Core Functions:** Operations Managers, HR & People Operations, Marketing & Growth Executives, Business Analysts, Executive Assistants, Client Relations, Legal & Compliance Officers.
- **Current Relationship with AI:** They already have access to or occasionally use ChatGPT, Gemini, or Claude in their daily workflow.
- **Primary Pain Points:**
  1. *Unreliable Outputs:* Results swing wildly between brilliant and completely off-target, hallucinated, or unformatted.
  2. *Wasted Editing Time:* Users spend 15–20 minutes manually reformatting and fixing AI drafts, defeating the purpose of AI automation.
  3. *Blind Tweaking:* When an AI output misses the mark, users don't know *why* it failed—they blindly add random words ("please be professional", "think step-by-step") without understanding the missing structural component.
  4. *Data Privacy Hesitation:* Fear of pasting confidential customer or company data into public models.
- **What Success Looks Like for Them:**
  Being able to draft a prompt for a complex workplace task (e.g., an executive summary, a customer dispute resolution, or structured data extraction) and get an **audit-ready, boardroom-quality output on the first or second attempt**.

## 7. Current User Flow Audit (Task 4)

### Current User Path (High Friction):
```
[1. Landing Page]
       │
       ▼
[2. Google Sign In]
       │
       ▼
[3. Class Selection Screen] (Modal / Screen requiring choice)
       │
       ▼
[4. Learner Dashboard / Home] (Course card list, stats, circular progress)
       │
       ▼
[5. Click "Start Lesson"]
       │
       ▼
[6. Lesson Brief / Theory Screen] (Context, instructions, hints)
       │
       ▼
[7. Prompt Editor] (Write prompt)
       │
       ▼
[8. Run AI Button] (Wait for response)
       │
       ▼
[9. Scroll Down to Output] (Output pushed below editor)
       │
       ▼
[10. Scroll Down to Rubric Evaluation] (Scorecard pushed even further down)
       │
```

- **Pain Points:** 10–11 distinct steps. Constant page transitions and long vertical scrolling disconnect the Prompt from the Output and Evaluation. User loses context between what they typed and what AI generated.

## 8. Proposed User Flow: "One Workspace, Fewer Steps"

### Target Flow:
```
[1. Landing Page] ──(1-Click Google Login)──► [2. Quick 2-Question Onboarding] (First time only)
                                                               │
                                                               ▼
                                               [3. UNIFIED AI PLAYGROUND]
                                               ┌────────────────────────────────┐
                                               │ Left: Task & Prompt Composer   │
                                               │ Right: Output & Live Rubric    │
                                               │ Drawer: Instant Lesson Switch  │
                                               └────────────────────────────────┘
```

### Detailed Transition & Step Consolidation:

| Current Step | Proposed Status | Implementation Strategy |
| :--- | :--- | :--- |
| **Landing & Login** | **Preserved (Optimized)** | 1-click Google OAuth directly into the active session. |
| **Class Selection Screen** | **Eliminated from main flow** | Auto-enrolls into the assigned/default cohort. Class switcher is an understated dropdown in the top navbar. |
| **Learner Dashboard Page** | **Merged into Workspace Drawer** | Instead of forcing users to return to a full dashboard to pick a lesson, a lightweight slide-over Drawer or Header Dropdown allows switching lessons in 1 click. |
| **Theory / Brief Screen** | **Inline Collapsible Panel** | The task brief and data context live directly in the left column above/beside the editor; theory is available on-demand via an expandable drawer, never a blocking screen. |
| **Prompt Editor** | **Primary Left Panel** | Stays visible at all times. Natural language editing with tag scaffolding. |
| **Output & Evaluation** | **Persistent Right Panel** | Placed side-by-side with the editor on desktop (>=1280px). No scrolling down miles to see results. |
| **Step 1 / 2 / 3 Navigation** | **Integrated Version Bar** | Attempts and progressive difficulty are handled as version tabs (`v1`, `v2`, `v3`) within the same screen. |

**Step Count Reduction:**  
From **10 steps down to 2 steps** (Landing → Workspace) for returning users, and **3 steps** (Landing → 2-Question Onboarding → Workspace) for first-time learners.

## 9. Onboarding Specification (Task 5)

### Design Constraints:
- Maximum 2 questions.
- Takes less than 20 seconds to complete.
- Non-intrusive: every question has a clear functional outcome on the app UI.
- Skippable: default fallback applies if user clicks "Start immediately".

---

### Question 1: "How do you usually work with AI today?"
*Purpose: Determines the default Workspace Layout Preset.*

- 🔘 **A. Conversation & Chat (Like ChatGPT/Claude)**  
  *Outcome:* Sets layout to **Chat-First Preset** (familiar sequential chat thread with inline evaluation pills).
- 🔘 **B. Document & Side-by-Side Drafting**  
  *Outcome:* Sets layout to **Workspace / Split-View Preset** (pro dual-column playground).
- 🔘 **C. I'm completely new / Step-by-Step Guidance**  
  *Outcome:* Sets layout to **Guided Learning Preset** (with visible hints, structure checklists, and walkthrough coach).

---

### Question 2: "What business deliverables do you create most frequently?"
*Purpose: Pre-filters curriculum recommendations and customizes sample placeholder prompts.*

- 🔘 **A. Executive Communications & Memos** (Emails, briefings, stakeholder updates)
- 🔘 **B. Operations & Document Processing** (SOPs, customer dispute triage, summaries)
- 🔘 **C. Data Analysis & Reporting** (Extracting tables, financial synthesis, status tracking)

---

### Generated Learner Preference Profile:
```typescript
interface LearnerPreferenceProfile {
  interactionPreset: 'chat_first' | 'split_workspace' | 'guided_learning';
  primaryDomain: 'executive' | 'operations' | 'analytics';
  onboardingCompleted: boolean;
}
```
*User immediately lands on Lesson 1 of their recommended curriculum with their preferred layout preset applied.*

## 10. Adaptive UI Architecture (Task 6)

### Key Architectural Principle:
**One Component System. One Backend. One Pedagogical Logic.**  
We do NOT build 3 separate applications. We provide 3 **layout configurations** of the exact same underlying components (`PromptComposer`, `OutputViewer`, `RubricScorecard`, `LessonBrief`).

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                               SHARED COMPONENT FOUNDATION                              │
│   • PromptComposer   • OutputPanel   • RubricScorecard   • VersionBar   • TaskBrief    │
├──────────────────────────┬─────────────────────────────┬───────────────────────────────┤
│    PRESET 1: WORKSPACE   │     PRESET 2: CHAT-FIRST    │    PRESET 3: GUIDED LEARNING  │
│        (Dual-Pane)       │      (Sequential Feed)      │       (Scaffolded 3-Col)      │
└──────────────────────────┴─────────────────────────────┴───────────────────────────────┘
```

---

### Comparison of the 3 Adaptive Presets:

| Dimension | Preset 1: Workspace / Split-View (Pro) | Preset 2: Chat-First (Familiar) | Preset 3: Guided Learning (Scaffolded) |
| :--- | :--- | :--- | :--- |
| **Best For** | Business Analysts, Ops, Power Users | Users heavily conditioned by ChatGPT/Claude | Beginners, corporate cohort workshops |
| **Navigation** | Minimalist top bar; Drawer for curriculum | Clean single-column with side history rail | Progress step bar (Step 1 → 2 → 3) |
| **Prompt Placement** | Left column, multiline editor with tag toolbar | Bottom anchored input bar (expandable) | Center column with modular section slots |
| **Output Placement** | Right column, directly beside prompt | Appears inline in chat feed as AI reply | Right column with line-by-line highlight |
| **Task / Context** | Collapsible header or left tab | Pinned top system card in thread | Left permanent column with rubric rules |
| **Feedback Placement** | Attached below Output in right column | Collapsed scorecard pill under AI response | Dynamic score card updating with each keystroke |
| **Tutorial Behavior** | Tooltips on first visit; manual icon | Natural coaching messages inside chat | Guided step-by-step walkthrough modal |

*User can toggle between presets at any time via a clean switch in the top header.*


### Key Layout Principles Implemented:
1. **Zero-Scroll Comparison:** Prompt on the left, Output on the right. User never scrolls down to inspect what the AI produced.
2. **Context Accessible Without Blocking:** Task memo is a compact header card with an expandable preview that does not steal height from the editor.
3. **Independent Scroll Regions:** If the AI output is long, only the right pane scrolls; the Prompt Composer stays pinned in view.
4. **Immediate Rubric Visibility:** The rubric scorecard lives directly underneath the output in the same panel.

---

### Mobile & Tablet Wireframe (<1024px)
On mobile devices, layout gracefully shifts from Dual-Pane to a **High-Utility 2-Tab Workbench**:
- Tab 1: **Prompt & Context** (Full-screen focused writing).
- Tab 2: **Output & Scorecard** (Auto-switches to Tab 2 immediately when user taps "Run AI").
- Floating Bottom Bar: Quick toggle `[ Prompt (Draft) | Output (92/100) ]` with notification dot when new output is generated.

## 12. Visual Direction & Design Tokens (Task 8)

### Core Visual Philosophy:
- **Tone:** "Light Professional Workspace" (inspired by Linear, Raycast, and Notion)—clean, high-density, serious, and distraction-free.
- **Unified Visual Language:** Landing Page and In-App Playground share the exact same typography, surface colors, borders, and button styles.
- **No AI SaaS Slop:** No purple/violet neon glows, no floating robot cartoons, no animated sparkles on every button, no dark-mode sci-fi themes.

---

### Design Token System:

| Token Category | Value / Specification | Rationale |
| :--- | :--- | :--- |
| **Surfaces** | Canvas: `bg-slate-50` (`#F8FAFC`)<br>Card: `bg-white` (`#FFFFFF`)<br>Panels: `bg-slate-50/70` border `border-slate-200/80` | High readability, clean contrast, crisp white cards on soft off-white canvas. |
| **Typography** | Sans: `Inter` or `Plus Jakarta Sans` for UI & prompts<br>Mono: `JetBrains Mono` strictly for tags & code<br>Scale: H1 (28–32px), Body (14–15px), Meta (11–12px) | Standard sans-serif for natural language prompt writing; mono reserved for technical data tokens. |
| **Action Colors** | Primary Action: `emerald-700` (`#047857`) hover `emerald-800`<br>Accent/Focus: `emerald-500` ring<br>Pass State: `emerald-50` + `text-emerald-800` | Emerald green signifies precision, growth, correctness, and business reliability. |
| **Status Colors** | Danger / Red Card: `rose-500` / `rose-50`<br>Warning / Needs Work: `amber-500` / `amber-50`<br>Neutral Meta: `slate-500` | Universally understood corporate status indicators. |
| **Corners & Borders** | Cards: `rounded-2xl` (16px)<br>Buttons & Inputs: `rounded-xl` (12px)<br>Chips & Badges: `rounded-lg` (8px)<br>Borders: `border border-slate-200` (1px) | Modern soft corners without looking overly bubbly or toy-like. |
| **Elevation / Shadows** | Default Cards: `shadow-2xs` (`0 1px 2px rgba(0,0,0,0.04)`)<br>Modals / Drawers: `shadow-xl` | Extremely subtle shadows. Visual hierarchy achieved through borders and background tone differences. |
