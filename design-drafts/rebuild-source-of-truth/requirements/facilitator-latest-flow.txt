📐 Facilitator UI Refactoring Framework & Design Methodology
1. Core Philosophy: Intent-Driven Operational Hierarchy
Traditional admin dashboards present a flat menu of equal-weight options, causing cognitive fatigue. Our framework replaces this with an Intent-Driven Operational Hierarchy that adapts the UI based on what phase of work the facilitator is performing rather than forcing them to hunt for features.


2. The 6 Core Design Principles
Principle 1: 3-Phase Operational Hierarchy ("Observe → Prepare → Execute")
Every Facilitator UI must align with or connect to one of three operational phases:

Phase 1: Situational Awareness ("The Pulse") — Observe & Assess
5-second health check: active cohorts, average rubric scores, stuck/PII alerts, and model latency.
Adaptive hero banner that auto-promotes live sessions when active (\(\pm 30\) mins) or authoring tools when idle.
Phase 2: Pre-Game Studio ("Prepare & Govern") — Build & Configure
Everything needed to author Codelabs, set system prompts, attach SOP PDFs, verify RAG vector embeddings, and adjust 5-criteria rubric weights before class.
Phase 3: Live War Room ("Execute & Intervene") — Monitor & Guide
Real-time 5-technique heatmaps, automated stuck learner flags (>5 failed attempts), quick broadcast hints, and 1-on-1 verbatim prompt inspection.
Principle 2: Dual-Layer Interaction Pattern ("Quick Inline vs. Deep Navigation")
To prevent unnecessary full-page reloads for routine tasks, every interface must offer two interaction depth levels:

Layer A (Quick Inline Control): High-frequency, low-friction actions performed directly on main views or cards (e.g., inline lifecycle status toggles Draft → Active, quick cohort reassignments, inline SLA hint broadcasts).
Layer B (Deep Workspace Navigation): Dedicated, full-featured modal drawers or specialized pages (UI-10, UI-11) for multi-step, complex operations (e.g., editing system instructions, examining V1..V5 verbatim syntax diffs).
Principle 3: Zero-Dead-End Navigation Triad (UI-09 ↔ UI-10 ↔ UI-11)
No facilitator UI should exist as an isolated island. Every view must provide bidirectional navigation triggers to its counterpart screens while preserving state and context (learnerId, labId, cohortId):

UI-09 → UI-10: Click learner card on Live Heatmap \(\rightarrow\) Open Inspector Drawer.
UI-10 → UI-09: Click "Close Drawer" \(\rightarrow\) Return to Live Heatmap.
UI-09 → UI-11: Click "Edit Lab" or "+ Create Lab" \(\rightarrow\) Open Curriculum Studio.
UI-11 → UI-09: Click "Deploy & Launch War Room" \(\rightarrow\) Return to Control Center.
UI-10 → UI-11: Click "Edit Master Template" (when multiple students fail the same step) \(\rightarrow\) Jump directly to edit the Codelab template in Studio.
UI-11 → UI-10: Click "Inspect Baseline Runs" \(\rightarrow\) View sample or historical attempt logs.
Principle 4: Strict Enterprise Domain & Data Schema Alignment
All copy, data fields, and system logic must strictly ground in the Intrepid Asia enterprise scenario:

Real-world Context: LAB-BS-03: One-shot Brand Voice & SLA Ticket Classification (11.11 Mega Sale Ticket #842 double payment dispute).
Ground-Truth RAG SOP: Grounded against SOP-Campaign-Ops-v4.pdf (Page 4: P1 Critical SLA 15-min window).
5 Weighted Rubric Criteria: Synchronized across all UIs:
Groundedness & SOP Citation (30%)
Task & Role Persona (20%)
Format Adherence - Markdown Table (20%)
One-Shot Pattern Compliance (15%)
Business Actionability & SLA Window (15%)
Principle 5: Actionable Observability & Cognitive Safeguards
Automated Red Flags: Visual badges and red highlights trigger automatically when a student makes \(>5\) failed attempts ("Stuck") or inputs unscrubbed sensitive data ("PII Breach").
Gated Cognitive Safeguards: Hints and solutions in learner views remain locked behind confirmation modals to prevent passive copying and protect learning integrity.
Real-time Telemetry: Stream live latency, token counts, and execution timestamps (e.g. 0.72s • 184 tokens).
Principle 6: Standardized M3 Visual & Color-Coded UX Hierarchy
Design Tokens: Material Design 3 (M3) palette using Inter for UI text and JetBrains Mono for prompts, code, and telemetry.
Color-Coded Status Tokens:
🟢 Emerald (#059669): Completed, Passed (score \(\ge 8.0/10\)), Active state, Successful execution.
🟡 Amber (#D97706): In Progress, Published state, Warning/Hint.
🔴 Rose (#BA1A1A): Stuck learner (\(>5\) fails), Failed evaluation, Archived state.
🟣 Purple (#7E22CE): PII Breach, Advanced Tier, SOP/RAG Indexing.
🔵 Blue (#0B57D0): Primary actions, Draft state, Role personas.

Key UI Mapping Summary
UI-00: Login & Role Authentication.
UI-05: Learner Codelab Workspace (receives broadcast SLA hints, private coaching tips, and session freeze overlays).
UI-08: Ground-Truth SOP Context Library (RAG indexing and document citation verification).
UI-09: Facilitator Control Center (central hub for Phase 1 telemetry, Phase 2 inline status toggles, and Phase 3 live heatmap monitoring).
UI-10: Prompt Inspector Drawer (verbatim V1..V5 syntax review, 5-criteria diagnostic scores, and 1-on-1 private coaching).
UI-11: Curriculum & SOP Studio (deep lab creation, system prompt editing, SOP linking, and rubric weight tuning).
UI-12: L&D Admin Impact Analytics (receives post-workshop telemetry and score syncs).
